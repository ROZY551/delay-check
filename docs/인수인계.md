## 5. 동작 흐름

### 편명 조회 (홈)
1. `home.py`의 `search_form()`에서 편명·날짜·시각 입력 → "지연 확률 확인"
   - 출발 시각 기본값은 **지금 + 1시간** (편명과 상관없음 — 9번 '출발 시각 확인' 참고)
2. `services.run_prediction()`
   - `Predictor.find_flight()`: `편명_조회표.csv`에 없으면 `None` → 화면이 `view="notfound"`로 바뀜
   - `services.weather_for()` → `weather.get_weather()`
     - 출발이 지금이거나 지났음 → **초단기실황**
     - 5시간 이내 → **초단기예보** (없으면 단기예보)
     - 그 뒤 ~ 3일 → **단기예보**
     - 그 시각 예보가 없으면 앞뒤 **2시간** 안의 가장 가까운 예보 (`NEAREST_HOURS`), 출처에 "(9시 예보)" 표시
     - 실패(키 없음, 서버 오류, 예보 없음) → `WeatherError` → **그 달의 평균 날씨**(`월별_평균날씨.csv`)로 대체, 화면에 안내
   - `Predictor.predict()` → 확률, 단계(낮음/보통/높음), 근거 3줄, 안내 문구
   - 로그인 상태면 `auth.add_history()`로 기록 저장 (10개 넘으면 오래된 것 삭제)
3. `view="result"` → 요약 카드, 날씨 카드, 근거 카드, 시간대 그래프

### 편 비교
- `services.day_weather()` → `weather.get_day_forecast()`: 그날 0~23시 예보를 한 번에 가져옴 (3시간 간격이면 가까운 시각으로 채움)
- `Predictor.compare()`: 그 목적지의 **여객편 중 운항 30회 이상**인 편을 **평소 출발 시각**으로 예측, 낮은 순으로 정렬. 예보가 없는 시간대(오늘 이미 지난 시각 등)의 편은 `avg_weather=True` → 표에 '평균 날씨'

### 모델 입력 (10개)
범주형: 항공사, 도착지, 구분 / 숫자: 시, 요일, 월, 풍속(KT), 기온(℃), 강수량(mm), 편명지연율
- 기상청 풍속은 m/s라서 **KT로 바꿔서** 넣어요 (학습 데이터 AMOS가 KT라서). `ms_to_kt()`
- 강수량은 "1mm 미만", "30.0~50.0mm" 같은 글자로 와서 숫자로 바꿔요. `parse_precip()`

### 단계 기준
15% 미만 **낮음** · 15~35% **보통** · 35% 이상 **높음** (`predictor.py`의 `LOW, HIGH`)
모델의 판정 기준(threshold) 0.26, 학습 데이터 평균 지연 비율 21.1%

### models/ 폴더의 파일
| 파일 | 내용 |
|---|---|
| `지연예측_모델.joblib` | dict: `pipeline`(원-핫 + XGBoost 트리 400개), `cat_cols`, `num_cols`, `threshold`, `prior` 등 |
| `편명_조회표.csv` | 편명 2,360개 → 항공사·도착지·구분·운항횟수·편명지연율·평소출발시·평소출발시각 (예: KE705 → 18:35, 운항 393회) |
| `시간대별_지연비율.csv` | 0~23시 평균 지연 비율 (그래프·슬라이드 숫자도 여기서 계산) |
| `월별_평균날씨.csv` | 1~12월 평균 풍속·기온·강수량 (예보 실패 시 사용) |

### session_state 키 (화면 상태)
| 키 | 뜻 |
|---|---|
| `view` | `"home"` / `"result"` / `"notfound"` |
| `result` | 마지막 예측 결과 dict |
| `flight_no`, `dep_date`, `dep_time` | 조회 입력칸 값 |
| `notfound_no` | 없는 편명 화면에 보여줄 편명 |
| `user` | 로그인 정보 `{id, username, name}` (없으면 로그아웃 상태) |
| `big_text` | '큰 글자' 토글 |
| `cmp_result`, `cmp_dest`, `cmp_day` | 편 비교 결과와 입력값 |

## 7. 꼭 알아야 할 함정 (실제로 겪은 것)

1. **Colab 모델이 Windows에서 안 열림** → `XGBoostError: input stream corrupted`
   - 파일이 손상된 게 아니에요. xgboost 3.4는 모델 안에 난수 상태(`rng_state`)를 글자로 저장하는데, 이 형식이 Linux(10진수 625개)와 Windows(16진수 624개)에서 달라요.
   - `backend/model_loader.py`의 `load_bundle()`이 열리지 않을 때만 이 값을 이 PC 형식으로 바꿔서 다시 열어요. 예측에는 쓰이지 않는 값이라 결과는 같아요.
2. **`requirements.txt`에 한글을 쓰면 Windows에서 `pip install`이 실패해요** (cp949로 읽다가 `UnicodeDecodeError`). 주석은 영어로 쓰세요.
3. **라이브러리 버전**: 모델은 scikit-learn **1.6.1**, xgboost **3.4.1**로 저장됐어요. 둘 다 `==`로 고정돼 있어요. 모델을 다시 만들면 Colab에서 `import sklearn, xgboost; print(sklearn.__version__, xgboost.__version__)`로 확인하고 맞추세요.
4. **3일 뒤 단기예보는 3시간 간격**(0·3·6…21시)으로 와요. 정확히 같은 시만 찾으면 대부분 평균 날씨가 돼 버려서, 가까운 시각(±2시간)을 쓰게 고쳤어요.
5. **한국 시간**: 서버(Cloud)는 UTC라서 시간은 모두 `KST`(`backend.weather.KST`) 기준으로 계산해요. 새 코드에서 `datetime.now()`를 그냥 쓰지 말고 `datetime.now(KST)`나 `services.today_kst()`를 쓰세요.
6. **`.streamlit/` 위치**: Streamlit은 실행한 폴더의 `.streamlit/`을 읽어요. 그래서 꼭 저장소 맨 위에서 `streamlit run app/main.py`로 실행해야 테마와 키가 적용돼요.
7. **초단기예보 풍속이 0.2KT처럼 아주 낮게 나올 때**가 있어요. 바람 방향이 바뀌는 시각의 실제 예보값이라 버그가 아니에요.
8. **Git 줄바꿈 경고**(`LF will be replaced by CRLF`)는 Windows 설정(`core.autocrlf=true`) 때문이고 무시해도 돼요. 모델 파일은 바이너리로 인식돼서 바뀌지 않아요.
9. **Streamlit 버전을 올리면 깨질 수 있어요.** 코드가 `use_container_width=`와 `st.components.v1.html`을 쓰는데, Streamlit이 없앤다고 예고한 기능이에요 (실행하면 경고가 나와요). 그래서 `streamlit==1.66.1`로 고정했어요. 올리려면 먼저 `use_container_width=True` → `width="stretch"`, `components.html` → `st.iframe`으로 바꾸고 테스트하세요.
10. **CSS 선택자는 실제 화면 구조를 보고 써야 해요.** Streamlit 1.66 기준:
    - 폼 안 버튼은 `kind="primaryFormSubmit"` / `"secondaryFormSubmit"` (그냥 `kind="primary"`가 아님)
    - 날짜·시각 칸은 `<input>`이 아니라 `[role="group"]` 안의 글자 조각, 목록 칸 값은 `[data-testid="stSelectbox"] input`
    - 아이콘은 `[data-testid="stIconMaterial"]`, 안내 상자 아이콘은 `…DynamicIcon` — 글꼴을 넓게(`[class*="st-"]`) 지정하면 아이콘이 `schedule` 같은 **글자로 보여요** → `style.py` 맨 위에서 아이콘 글꼴을 되돌려 둠
    - 입력 회색 칸은 기본 40px, 메뉴 띠도 높이가 고정돼 있어서 안쪽을 키우면 **넘쳐요** → 바깥 칸 높이까지 같이 지정
    - 그래프 도구 버튼은 `[data-testid="stElementToolbar"] button[aria-label="Download as PNG"]` 등
11. **`style.py`의 CSS는 `%` 서식 문자열**이에요 (`CSS % {...}`). 그래서 CSS 안의 `%`는 반드시 **`%%`**로 써야 해요 (`100%%`, `calc(100%% - 72px)`). 한 번 `100%`로 써서 앱 전체가 `TypeError: not enough arguments for format string`으로 안 열렸어요. 고친 뒤 확인:
    ```
    .venv/Scripts/python -c "import sys; sys.path.insert(0,'app'); from frontend.components import style; style.CSS % {'fonts':'','bg':'','navy':'','amber':'','zoom':''}; print('OK')"
    ```
12. **로컬 서버는 `style.py`·`charts.py` 같은 모듈을 고쳐도 자동으로 다시 읽지 않아요.** 화면이 그대로면 서버를 끄고(Ctrl+C) 다시 `streamlit run app/main.py`.

## 9. 결정 대기 · 남은 과제

### 결정 대기 (사용자가 기능 테스트 후 정함)

**① 출발 시각 확인** — 지금은 입력한 시각을 확인 없이 그대로 계산해요
- 예: KE705는 평소 **18:35** 출발인데, 15:00을 넣어도 "15시 출발이면 35%"로 계산함. 출발 시각 칸 기본값이 '지금 + 1시간'이라 생기기 쉬움
- 데이터 한계: `편명_조회표.csv`에는 편명마다 **평소 출발 시각 1개 + 13개월 운항 횟수**만 있고 날짜별 운항표는 없어요. 그래서 "그날 그 편이 실제로 뜨는지"는 확인 불가. 편명 절반은 운항 18회 이하(드문 편)
- 제안했던 방법 (사용자: "그렇게는 진행하지 말고 우선은 보류"):
  - 입력 시각이 평소 시각과 1시간 넘게 다르면 결과 화면에 "KE705는 평소 18:35에 출발해요" + [18:35로 다시 계산] 버튼
  - 운항 30회 미만 편에는 "그날 운항하지 않을 수 있어요" 안내
  - 또는 시각을 받지 않고 늘 평소 시각으로 계산
- 넣는다면 고칠 곳: `home.py` 결과 부분, `predictor.find_flight()`의 `평소출발시각`·`운항횟수`, 테스트 추가

**② 이미지 업로드** — 과제 핵심 기능 목록에 있지만 지금 없음. 필수인지 확인 필요
- 방안: (가) 탑승권 사진 → 편명·날짜 자동 입력 (OCR 필요, 가장 큼) (나) 홈 슬라이드 배경 사진 올리기 (`hero.py`에 `photo` 자리 있음, 쉬움, 예측과 무관) (다) 결과 화면 이미지 저장 (업로드가 아니라 다운로드)
