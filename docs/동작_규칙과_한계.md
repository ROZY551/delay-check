# 동작 규칙과 한계

## 모델

- 파일: `app/backend/models/지연예측_모델.joblib`. 원-핫 인코더와 XGBoost(트리 400개)를 묶은 Pipeline이에요.
- 입력 변수: 항공사·도착지·구분(범주형), 시·요일·월·풍속(KT)·기온(℃)·강수량(mm)·편명지연율(숫자)
- 판정 기준(threshold) 0.26, 학습 데이터 평균 지연 비율 21.1%
- 학습 데이터: 인천공항 출발편 2025년 9월 ~ 2026년 9월, 237,575편, 편명 2,360개

| 파일 | 내용 |
|---|---|
| `편명_조회표.csv` | 편명 → 항공사·도착지·구분·운항횟수·편명지연율·평소 출발 시각 |
| `시간대별_지연비율.csv` | 0~23시 평균 지연 비율 (그래프·슬라이드 숫자도 여기서 계산) |
| `월별_평균날씨.csv` | 예보를 못 불러올 때 쓰는 월평균 날씨 |

데이터에서 따로 계산해 둔 숫자(월별 최다·최소, 비 올 때 비율, 학습 편수)는 `app/frontend/components/hero.py`의 `STATS`에 있어요. 데이터를 바꾸면 여기도 같이 고쳐야 해요.

## 화면 동작 규칙

| 상황 | 처리 |
|---|---|
| 출발 날짜 | 오늘 ~ 3일 뒤만 고를 수 있음 (기상청 예보 범위) |
| 출발까지 0시간 이하 / 5시간 이내 / 그 뒤 | 초단기실황 / 초단기예보 / 단기예보 |
| 예보를 못 불러옴 (키 없음, 서버 오류) | 그 달의 평균 날씨로 계산하고 화면에 안내 |
| 편 비교에서 예보가 아직 없는 시간대 | 그 편만 월평균 날씨로 계산, 표에 '평균 날씨' 표시 |
| 조회표에 없는 편명 | 예외 화면 + 예시 편명 버튼 |
| 단계 | 15% 미만 낮음 · 15~35% 보통 · 35% 이상 높음 |
| 로그인 상태에서 조회 | 조회 기록에 자동 저장 (최근 10개) |
| 로고 클릭 | 입력값을 지우고 처음 화면으로 |
| 시간 | 서버가 UTC여도 한국 시간(KST) 기준 |

## 한계 (결과보고서용)

- 학습에는 실제 **관측** 날씨를 썼고, 예측에는 **예보** 날씨를 써요. 예보가 빗나가면 결과도 달라질 수 있어요.
- 지연의 가장 큰 원인인 '앞 비행편 지연(항공기 연결)' 정보는 입력에 없어요.
- 데이터가 13개월이라 태풍·폭설 같은 드문 날씨는 표본이 적어요.
- Streamlit Cloud에서는 앱이 재시작되면 회원·기록 DB가 지워질 수 있어요.
